# Reproduction

## What `run_all.sh` does

`run_all.sh` regenerates every derived output of this pack offline, from the
vendored inputs only (no network, no benchmark re-run):

1. `python3 build_derived.py` — regenerates `results/timing_table.csv/.md`,
   `results/size_table.csv/.md`, `results/cost_model.json/.csv`,
   `results/summary.txt`, and `docs/index.html` from
   `results/benchmark_*.json` and `results/environment.json`.
2. `bash verify_digests.sh` — regenerates `SHA256SUMS` and verifies it
   (39 files in the final pack, 0 failures).

Benchmarks are **not** re-run by `run_all.sh`: timings vary run to run, so
re-running them cannot reproduce byte-identical tables. The raw benchmark
logs (`results/raw_*.log`) are shipped unedited. To re-run the benchmarks
themselves, use `bash harness/build_benchmarks.sh` (needs a PQClean checkout
at the pinned commit and a liboqs 0.16.0 install) followed by
`bash harness/run_benchmarks.sh`, then re-run `run_all.sh` to re-derive the
tables.

## Fresh-copy reproduction (final run)

Procedure, run after the last numbers update:

```sh
rm -rf /tmp/pack-repro-lattice4
cp -r <pack> /tmp/pack-repro-lattice4
cd /tmp/pack-repro-lattice4
bash run_all.sh
```

- **Exit code: 0.** Console log of that run is shipped as
  `results/run_log.txt` (41 lines).
- **Byte-identical derived outputs (8/8):** `results/timing_table.csv`,
  `results/timing_table.md`, `results/size_table.csv`,
  `results/size_table.md`, `results/cost_model.json`,
  `results/cost_model.csv`, `results/summary.txt`, `docs/index.html`.
  `results/environment.json` (a vendored input, not regenerated) also
  matched byte-for-byte.
- **SHA256SUMS differed, as expected, for exactly 4 files:**
  `README.md`, `call_sites.md`, `claim_evidence_index.md`,
  `docs/index.html`. The shipped manifest predated the final numbers
  update to those four files; the fresh copy regenerated the manifest from
  the updated files. No other file differed.
- **Digest check: 38/38 files OK, 0 failures** (`bash verify_digests.sh
  --check`). That run predated this `REPRODUCTION.md` file, so its
  manifest covered 38 files; the final shipped pack has 39 (this file
  added) and its final check is 39/39, 0 failures (see below).

The same `run_all.sh` was also run in place in the pack afterwards:
exit 0, `SHA256SUMS` and `docs/index.html` unchanged.

## `results/run_log.txt`

`run_log.txt` is the raw console log of the fresh-copy reproduction run
above, captured and placed after the run. It is **not** regenerated by
`run_all.sh` — re-running `run_all.sh` leaves it untouched — so the shipped
copy is the exact log of the reproduction that produced the shipped
manifest.

## `results/digest_check_output.txt` and the fixed point

`digest_check_output.txt` is the raw output of
`bash verify_digests.sh --check` (39 lines of `./path: OK` in the final
shipped pack). It is captured
after the run log is placed, because `SHA256SUMS` covers `run_log.txt` too.
The fixed point works because the check output contains only
`./path: OK` lines — no hashes — so it is stable under regeneration:
the shipped `digest_check_output.txt` is byte-identical to the output of a
fresh `bash verify_digests.sh --check` run against the shipped pack.

Sequence used for the final state:

```sh
cp <fresh-copy console log> results/run_log.txt
python3 build_derived.py
bash verify_digests.sh
bash verify_digests.sh --check > /tmp/digest_final.txt
cp /tmp/digest_final.txt results/digest_check_output.txt
python3 build_derived.py
bash verify_digests.sh
bash verify_digests.sh --check   # output byte-identical to the shipped file
```

## Executable bits

The `.sh` files in this pack are executable (`run_all.sh`,
`verify_digests.sh`, `harness/build_benchmarks.sh`,
`harness/run_benchmarks.sh`). A GitHub web upload strips the executable
bit; run every script with `bash script.sh` in that case.
