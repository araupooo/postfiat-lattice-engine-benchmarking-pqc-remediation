Lattice Engine Benchmarking and Core-Protocol PQC Remediation Assessment

Measured ML-KEM and ML-DSA costs across every parameter set, from two independent implementations on one fixed host and toolchain, mapped to the core-protocol call sites in postfiatd (pinned commit 0085a1ff885d6a446369cf73a4430f75af22be55), with a remediation assessment for the post-quantum migration.

Headline finding. On this host the classical scheme is the slow one. ECDSA-secp256k1 verification — the operation the consensus path performs 198 times per ledger per node — costs 558.113 µs (median, OpenSSL 3.0.13, measured), while ML-DSA-65 verification costs 54.167 µs (liboqs, measured) — about 10× faster. The migration's cost is therefore bandwidth, not CPU: a dual classical + ML-DSA-65 validation carries 51.587× the signature-related bytes of a classical one per ledger. ML-KEM-768 for a TLS handshake (keygen + encaps + decaps) costs 51.185 µs (liboqs) / 337.990 µs (PQClean clean).

Reproduction

bash run_all.sh

Regenerates every derived output offline from the vendored results JSON (results/benchmark_*.json), rebuilds this page, and verifies digests. Expected: exit 0, byte-identical outputs. See REPRODUCTION.md for the exact command and recorded result. To re-run the benchmarks themselves (not part of the offline reproduction — timings vary run to run), see harness/build_benchmarks.sh and harness/run_benchmarks.sh.

Limitations

  • Timings are for this host and toolchain only (AMD EPYC, ~1.5 GHz, gcc 13.3.0, -O2). They do not transfer to validator hardware; the ratios between schemes on one host are the portable part.
  • liboqs uses its optimized AVX2 path; PQClean clean is portable C. A production deployment would use optimized code for both schemes; the PQClean numbers are a conservative upper bound.
  • OpenSSL 3.5 was not measured (see the claim index): the system OpenSSL is 3.0.13, which has no native ML-KEM/ML-DSA.
  • Cost-model network inputs (N=66, 2 proposal rounds) come from the sibling migration pack; they are labelled source-derived, not measured here.
  • No ledger was compiled or run locally; no validation was forged or replayed against a live node.
